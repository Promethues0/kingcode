# 密评项目整体方案（密码应用三级系统）

> 文档定位：评估方（安服工程师）组织密评项目的总体方案。覆盖被测方《密码应用方案》编制要求、评估方测评组织、高风险预筛与合规基线。
> 依据口径：GB/T 39786-2021《信息安全技术 信息系统密码应用基本要求》、GB/T 43206-2023、GM/T 0054-2018（映射参考）、密评 FAQ（第四版）、政务指南（2020-09）。所有数字口径来自知识库，未命中权威口径的项一律标注「查不到」，不编造。
> 本文档为项目组织用方案，不构成正式密评结论。

## 1. 项目前提（先确认，缺一项则停在对应环节）

| 前提 | 状态 | 缺失时的动作 |
|---|---|---|
| 等保定级/备案 | 三级，需与等保备案等级一致（或高于） | 未备案用拟定等级，方案里注明 |
| 重要数据范围书面界定 | 已有 | —— |
| 系统上线时间 | 待确认 | **雷区**：2020-01-01 之后投运且未做上线前密评 → 直接判不符合（FAQ 27）；之前投运可判不适用 |
| 密码应用方案 | 待确认 | **存量系统无方案 → 第一优先补「密码应用改造方案」**（FAQ 26：改造方案可视为密码应用方案；同时清掉高风险 10.2「无方案」），这是成本最低、收益最大的一步 |
| 商用密码产品证书 | 待确认 | 清单表加列「证书编号+有效期」；2025-07-01 后采购的产品证书颁发单位须为「商用密码检测认证中心」（FAQ 2） |

## 2. 合规基线

- 依据标准：GB/T 39786-2021 第三级（四个技术层面 + 管理侧四块）。
- 指标助动词口径按第三级执行：**应**为强制、**宜**为推荐、**可**为可选；判定与方案自评均取标准原文词，不凭记忆（评估时逐条调指标库核对）。
- 量化结构：技术侧（物理和环境 / 网络和通信 / 设备和计算 / 应用和数据）70 分 + 管理侧（管理制度 / 人员管理 / 建设运行 / 应急处置）30 分。逐指标权重在测评打分阶段按指标库取，方案阶段不写死。
- 政务 vs 通用行业：
  - 政务：方案通过密评是立项必要条件、密评通过是验收必要条件；三级及以上每年至少一次密评。
  - 通用行业：无上述硬门槛，但 GB/T 39786 各级均要求「应制定密码应用方案」，无方案直接命中高风险 10.2。
  - 通用行业（非政务）的密评周期：**公开材料无权威口径，查不到**，不承诺天数/周期。

## 3. 分阶段路线

```
阶段 A 方案层     阶段 B 建设/改造   阶段 C 测评层     阶段 D 整改闭环
被测方编方案  →  按方案采购/改造 →  证据采集(授权) →  差距→整改台账
   ↓                  ↓               ↓                ↓
密评机构审方案       （变更需复审）   D/A/K判定+打分    复采→diff比对
   ↓                  ↓               ↓                ↓
通过→备案        上线前评估         报告+未测评声明    闭环/不整改(留证)
```

阶段要点：
- **A（当前阶段）**：被测方编《密码应用方案》（章节结构见 §4），评估方按 §5 的 15 条自检清单初审，交密评机构评审。
- **B**：按方案采购/部署；政务口径建设期改方案须再次确认。
- **C**：证据采集用 mpe-collect 产证据包（明细 .json / 摘要 .md）→ 校验 → 确定性预判 → 人工确认 → 打分。**网络探测须先取得书面授权（只认授权书，不认口头/文档字样）**。
- **D**：整改台账贯穿，闭环须证据非空；未测评项（无权限/够不到）出上下界区间，不按 0 计。

## 4. 被测方《密码应用方案》编制要求

章节结构（按政务指南模板映射到 GB/T 39786 口径，共 0–7 章）：

| 章 | 内容 | 关键要求 |
|---|---|---|
| 0 封面 | 项目名称 / 建设单位 / 编制日期 | |
| 1 背景 | 建设规划、法规要求、必要性 | |
| 2 系统概述 | 2.1 基本情况（含上线时间）、2.2 网络拓扑、2.3 业务情况（关键数据类型）、2.4 软硬件构成、2.5 管理制度 | 上线时间栏直接决定「上线前评估」指标怎么判，先想清楚再填 |
| 3 密码应用需求分析 | 按五个层面逐条对应第三级指标；**不适用的部分说明原因 + 替代性措施** | 需求分析清单表：层面/指标要求/密码应用需求/不适用说明 |
| 4 设计目标及原则 | 总体性、完备性、适用性、经济性 | 核心是「适用性」：不堆砌产品，做体系化设计 |
| 5 技术方案 | 5.1 技术框架图（与第 3 章需求对应）；5.2–5.5 四个技术层面各按**八要素**写；5.6 密钥管理；5.7 密码应用部署（产品清单+证书列+三条流部署图）；5.8 安全与合规性分析（合规对照表） | 八要素：密码保护对象/密码措施/密码子系统组成功能/密码产品及其遵循标准/密码服务/密码算法/密码协议与应用工作流程/密钥管理体系与实现 |
| 6 安全管理方案 | 人、制度、实施、应急四块 | 密码安全审计员不可与密钥管理员、密码操作员兼任（8.6b③）；三级应急报告向信息系统主管部门 |
| 7 实施保障方案 | 实施内容、计划（路线图+节点+交付物）、保障措施、经费概算 | 经费概算覆盖新增密码产品与服务 |

对照表铁律：方案是设计文档，合规性对照表取值**只有「符合」和「不适用」**，没有「不符合」。做不到的必须走「不适用 + 论证 + 替代性风险控制措施（等效控制）」。
密钥管理章节必须有：密钥种类、体系及全生命周期各环节（x.7b，各级「应」），缺失=建设运行层面直接失分。
排版要求：A4、正文仿宋四号 1.5 倍行距、各级标题加黑、外文缩写注明全称、不涉国家秘密——政务评审会挑，别忽略。

## 5. 送审自检 15 条（评审前逐条过）

1. 等级明确且与等保备案一致（L01）
2. 需求与第三级指标逐条对应（L02）
3. 技术框架图与需求一一对应，不堆产品（L03）
4. 四个层面每节写全八要素（L04）
5. 独立密钥管理章节，覆盖全生命周期（L05）
6. 产品清单有证书编号+有效期；产品等级达标（三级→GB/T 37092 二级+）（L06）
7. 2025-07-01 后采购产品证书颁发单位为商用密码检测认证中心（L07）
8. 对照表逐项自评，不适用项都有原因+替代性措施（L08）
9. 覆盖管理侧四块（占量化 30 分）（L09）
10. 避开 8 条无缓解高风险（见 §6）（L10）
11. 明确重要数据界定范围（L11）
12. 双活/裸光纤/第三方接口/云平台按 FAQ 口径说明（L12）
13. 实施计划有路线图、节点、交付物（L13）
14. 经费概算覆盖新增产品与服务（L14）
15. 排版、缩写全称、不涉密（L15）

## 6. 高风险预筛（一票否决闸，先筛再算分）

- 16 项高风险总表在测评阶段逐条过；其中 7.1/7.3/9.3/9.5/10.1 必须人工确认，证据包只够到 5.1/5.2/5.3 子集。
- 8 条**无缓解措施死条款**（命中即不符合，无挽回）在方案阶段就要避开：算法/技术/产品合规（5.1/5.2/5.3）、密钥管理 7 类严重隐患、存储机密性（9.3）等。
- **方案阶段最优先规避：高风险 10.2（未制定密码应用方案）**——存量系统补改造方案即清。
- 疑似命中（版本号启发式）永远按「待确认」处理，不直接否决。

## 7. 测评组织要点

- 测评对象粒度：按 FAQ 16 划粒度（设备/应用层对象划分直接影响分数），设备层对象粒度在证据采集前与客户对齐。
- 证据强度四态：direct 才可下结论；indirect 只出「需人工确认」；no_permission / out_of_scope 一律「未测评」，出上下界区间，不按 0 计分。
- 产品存在 ≠ 在用；协商到 TLCP ≠ A√（TLCP 套件里 RSA_* 系是 RSA，套件逐个看）；装了国密库推不出业务在用。
- 结论表述：每条判定带条款号+助动词原词；未测评项单列声明（原因+补证途径）；覆盖度如实写（采样台数、out_of_scope 层面、探测开关）。

## 8. 常见雷区清单

- 不可否认性（抗抵赖）：GM/T 0054 里四级才「应」，但 GB/T 39786 三级已是「宜」且权重 1——照 2020 版政务指南写三级方案跳过它是高频坑（legacy_mapping）。
- 物理层面：机房是租的/托管的/在云上，物理和环境安全层面判定口径先查 FAQ（有明确口径）。
- 云平台：报告有效期、双活链路、第三方接口均按 FAQ 口径处理，不自己发明。
- 证书过期：按 FAQ 3.1 处理，不作为「符合」证据。
- 多层嵌套加密（SM4(DES(data))）按 FAQ 5 判定。
